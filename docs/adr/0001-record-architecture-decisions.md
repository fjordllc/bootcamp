# 0001: 設計判断をADRで記録する

- 状態: 採用
- 日付: 2026-11-02

このADRは、導入PRのマージをもって採用となります。

## 背景

このリポジトリには開発ガイドラインや実装・運用ドキュメントがあります。一方で、設計上の判断について、背景や比較した案、選んだ理由をまとめて残す場所はまだありません。

将来同じ領域を変更する人が、現在の手順だけでなく、判断に至った理由も確認できるようにします。

## 決定

重要な設計判断を、日本語のMarkdownによるADRとして`docs/adr/`に記録します。1ファイルに1つの判断を書き、採番や状態の扱いは[記録ガイド](README.md)に従います。

このADRが記録するのはADRの導入だけです。過去の実装の理由を推測して記録したり、既存ドキュメントを一律に移行したりすることは求めません。

## 検討した案

- PRの説明やコメントだけに残す: コード変更と一緒に議論できますが、後から設計判断の理由を探すときに見つけにくいため、これだけには頼りません。
- 既存のガイドラインにすべて追記する: 現在のルールと過去の判断の経緯が混ざるため、ADRを分けて置きます。

## 結果・影響

判断の経緯をコードと同じリポジトリでレビュー・管理でき、将来の変更時に理由を探しやすくなります。一方で、重要な判断を記録し、状態や一覧を更新する小さな保守作業が必要になります。

既存の実装・運用ドキュメントは、引き続き現在の手順やルールを示す文書として扱います。
