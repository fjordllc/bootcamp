# 設計判断の記録（ADR）

ADR（Architecture Decision Record）は、何を決めたか、なぜそう決めたかを残す文書です。1ファイルに1つの判断を、日本語で記録します。技術名やファイルパスは元の表記を使います。

## 記録する判断

アーキテクチャ、依存ライブラリの選定、責務の境界、アプリ全体に関わる方針など、将来の変更時に理由を知る必要がある重要な判断を記録します。日常的な修正すべてにADRを書く必要はありません。過去の判断を一律に書き起こすことも求めません。

既存の実装・運用ドキュメントには現在の手順やルールを書き、ADRには判断時の背景、比較した案、選んだ理由を残します。

## 追加する手順

1. 同じ領域の既存ADRを読み、これまでの判断と理由を確認します。
2. [テンプレート](template.md)をコピーし、次の未使用番号でファイルを作ります。名前は4桁の連番と内容を表す英小文字のケバブケースにします（例: `0001-record-architecture-decisions.md`）。`template.md`は採番の対象外です。
3. 状態を「提案中」にして各項目を記入します。日付は判断を記録した日とし、採用時には採用日を記録します。関連するPRやissueがあればリンクします。
4. このページの一覧に番号、タイトル、状態、日付を追加し、通常のPRレビューで検討します。採用する内容はマージ時に「採用」となるよう、ADRと一覧を更新します。別の承認手続きは設けません。
5. マージ前に、並行するPRと番号が重複していないことを確認します。

## 状態と変更

| 状態 | 意味 |
| --- | --- |
| 提案中 | レビュー・検討中の判断 |
| 採用 | 採用され、現在有効な判断 |
| 廃止 | 後継の判断を設けず、適用をやめた判断 |
| 置き換え済み | 新しいADRの判断に置き換わった判断 |

採用した判断を変更するときは、新しいADRに変更の背景と理由を書きます。置き換える場合は、旧ADRを「置き換え済み」にし、新旧双方の「関連資料」に相互リンクを追加します。後継なしで適用をやめる場合も、新しいADRに理由を記録し、旧ADRを「廃止」にして相互リンクを追加します。状態や日付を変更したら一覧も更新します。

旧ADRの当時の背景や理由は残します。誤字や事実誤認の訂正はできますが、判断の変更を過去の記述の上書きだけで済ませないでください。
